# 计划工作台 · PlanHub

统一访问 SOP计划管理、订单分析、销量预测、线索声量和数据速查。各网页在自己的项目维护；门户只提供导航、原样挂载、代理和通用发布工具。

## 日常操作

| 需要做什么 | 操作 |
|---|---|
| 使用交付文件夹 | 在收到的文件夹根目录双击 `启动发布版工作台.cmd` / `停止发布版工作台.cmd` |
| 开发联调启动 / 停止 | 在源码目录双击 `启动本地门户.cmd` / `停止本地门户.cmd` |
| 新增静态或动态网页 | 双击 `接入新网页.bat`，按向导填写本机路径 |
| 你：准备交付文件夹 | 双击 `发布应用.bat`，输入 `0`，完成后复制自动选中的文件夹 |
| 排查开发联调接入 | 源码目录运行 `npm run diagnose` |

## 整套发布版：本机使用

1. 在 A 双击 `发布应用.bat`，输入 `0`。全部成功后会打开门户根目录的 `交付包/`，并选中本次的 `计划工作台-时间戳` 文件夹。**只需把选中的这一个文件夹完整复制到 B。** 自动打开失败时，按窗口显示的完整路径取文件夹，已完成的交付内容不受影响。
2. B 首次准备 Node.js 20+ 和装有各应用依赖的 Python。双击收到的文件夹根目录中的 `启动发布版工作台.cmd`，按提示核对旁边 `../PlanHub本地运行/config.local.json`；填好 Python，放入真实共享规则、共享输入及需要迁移的数据，再启动。详见[首次准备](docs/deployment.md#local-bundle)。
3. 新实例通过检查并稳定运行 3 秒后窗口自动关闭，浏览器访问默认地址 `http://127.0.0.1:4173/`。停止时双击同一文件夹根目录的 `停止发布版工作台.cmd`；关闭浏览器不会停止服务。

整包只运行其中经过校验的 `releases/应用ID/版本/payload/`，无需兄弟项目源码、IIS 或计划任务。数据、日志、规则和本机配置在外置运行目录；程序包不包含 Python 环境、业务数据或密钥。缺少依赖或真实规则会报错，不会用假数据补齐。这里只供运行电脑本机访问，使用本机账户身份，不提供 Windows 部门认证。

更新时把新旧交付文件夹并排放在同一父目录，保留 `PlanHub本地运行`，先停旧版再启动新版。换到其他父目录时，另行迁移整个外置运行目录并核对路径，或用 `--runtime` 指向原运行目录；工具不会自动搬动旧包或数据，旧包仍可原位使用。不能让开发版或其他版本同时写同一份数据；端口占用时不接管陌生服务。详细操作见[部署手册](docs/deployment.md)。

`发布应用.bat` 的日常交付出口只有 `交付包/计划工作台-时间戳/`。打包不自动传送或上线；失败时核对窗口列出的原因，不交付未完成的文件夹。**`部署新版本.bat` 继续保留给正式 IIS 方案的部署同事**，进阶操作集中在[部署手册附录](docs/deployment.md)，本机使用按上面的三步即可。

## 开发联调入口

开发环境首次准备 Node.js 20+，动态项目按各自依赖准备 Python。默认项目与门户同级；路径不同用 `config.local/` 配置，里面的本机设置不提交 Git。配置或代码更新后先停止再启动。以下命令从源码目录运行。

双击 `启动本地门户.cmd` 后，启动器等待服务启动并通过健康检查，成功后 **3 秒自动关闭窗口**，门户和业务服务继续在后台运行。失败或部分应用异常时保留窗口并显示错误，已启动的门户仍可继续使用。重复启动会复用同一工作区、相同代码和配置的健康实例。停止后台服务使用 `停止本地门户.cmd`，或在门户根运行 `npm stop`。停止命令会等待门户监听端口关闭后再报告完成。启动时显示“使用已有独立服务”的应用由原启动方式管理。

启动不会自动打开浏览器，按启动器显示的地址访问。窗口会打印实际日志目录；启动日志保存在 `artifacts/portal-launch-随机目录/stdout.log` 和 `stderr.log`。需要前台查看运行过程时，先用停止入口结束已运行的后台实例，再在门户根运行 `npm start` 并保留窗口，按 `Ctrl+C` 停止。

开发端口由门户接入配置的 target 决定，启动参数用 {port} 自动跟随；公共前缀用 {basePath}。正式 IIS 的公共地址、共享根和默认账号在 deployment.json 各填一次，各应用仍可显式覆盖。

正式运行使用固定版本发布包。Git 推送不等于上线；页面的数据刷新也不等于程序升级。源码和发布工具都可以留在内网，部署流程无需连接 GitHub 或外部发布平台。

## 数据与排查

动态网页的上传、保存和刷新由原应用处理。生产数据库、Excel、上传与设置保存在版本目录外，发布程序不会覆盖它们。刷新只能读取部署电脑可访问的来源；开发电脑的文件变化需要先上传或同步到约定目录。

发布版缺少共享规则时，在外置运行目录中放入真实 `config/shared_config.py`，或修改 `config.local.json` 的 `sopSharedConfig`；其他相对路径也按运行目录解析。开发联调仍按原配置使用真实规则，可通过 `--shared-config` 或 `SOP_SHARED_CONFIG` 指定。订单仓库的本机 `config/` 目录不随 Git 下载。

发布版失败时按窗口提示查看外置 `logs/` 和 `config.local.json`；本轮新服务会停止，日志保留。同一发布目录及配置的健康实例可重复启动复用。开发联调页面无法打开时运行 `npm run diagnose`。端口占用先使用对应停止入口，不按端口结束未知程序。

工作台首页仍为计划周期 Demo，勾选等演示状态仅保存在当前页面，不写入业务数据。
