# 计划工作台 · PlanHub

统一访问 SOP计划管理、订单分析、销量预测、线索声量和数据速查。各网页在自己的项目维护；门户只提供导航、原样挂载、代理和通用发布工具。

## 日常操作

| 需要做什么 | 操作 |
|---|---|
| 本机启动 / 停止 | 双击 `启动本地门户.cmd` / `停止本地门户.cmd` |
| 新增静态或动态网页 | 双击 `接入新网页.bat`，按向导填写本机路径 |
| 生成、发送发布包 | 开发电脑双击 `发布应用.bat` |
| 安装收到的新版本 | 部署电脑双击 `部署新版本.bat` |
| 排查接入 | 门户根目录运行 `npm run diagnose` |

首次准备 Node.js 20+，动态项目按各自依赖准备 Python。默认项目与门户同级；路径不同用 `config.local/` 配置，里面的本机设置不提交 Git。关闭浏览器不会停止服务；配置或代码更新后先停止再启动。

双击 `启动本地门户.cmd` 后，启动器等待服务启动并通过健康检查，成功后 **3 秒自动关闭窗口**，门户和业务服务继续在后台运行。失败或部分应用异常时保留窗口并显示错误，已启动的门户仍可继续使用。重复启动会复用同一工作区、相同代码和配置的健康实例。停止后台服务使用 `停止本地门户.cmd`，或在门户根运行 `npm stop`。

启动不会自动打开浏览器，按启动器显示的地址访问。窗口会打印实际日志目录；启动日志保存在 `artifacts/portal-launch-随机目录/stdout.log` 和 `stderr.log`。需要前台查看运行过程时，先用停止入口结束已运行的后台实例，再在门户根运行 `npm start` 并保留窗口，按 `Ctrl+C` 停止。

本地端口由门户接入配置的 target 决定，启动参数用 {port} 自动跟随；公共前缀用 {basePath}。B 的公共地址、共享根和默认账号在 deployment.json 各填一次，各应用仍可显式覆盖。

正式运行使用固定版本发布包。Git 推送不等于上线；页面的数据刷新也不等于程序升级。源码和发布工具都可以留在内网，部署流程无需连接 GitHub 或外部发布平台。

## 数据与排查

动态网页的上传、保存和刷新由原应用处理。生产数据库、Excel、上传与设置保存在版本目录外，发布程序不会覆盖它们。刷新只能读取部署电脑可访问的来源；开发电脑的文件变化需要先上传或同步到约定目录。

启动提示“共享业务规则不存在”时，需在内网找到或迁入 SOP 使用的真实 `shared_config.py`。订单仓库的本机 `config/` 目录不随 Git 下载。恢复默认位置后重新启动门户。其他位置可用 `--shared-config` 或 `SOP_SHARED_CONFIG` 指定，优先级高于本机配置。

页面无法打开先运行 `npm run diagnose`：404 检查发布文件与入口，502/超时检查独立服务日志；启动过程和后端日志位置可从上述启动日志查看。启动提示端口占用时先用停止入口，不要按端口结束未知程序。

工作台首页仍为计划周期 Demo，勾选等演示状态仅保存在当前页面，不写入业务数据。
