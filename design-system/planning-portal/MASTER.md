# 计划部数据平台 · 界面设计基准

确认日期：2026-11-03；品牌图标于 2026-11-04 更新。适用范围：统一门户外壳及其后续新增页面、组件；不适用于 iframe 内的子应用。门户任务不得修改子应用 UI、源码或行为，也不得通过注入、裁剪或响应改写间接修改。入口指引见根目录 `AGENTS.md`。

## 视觉依据与取舍

品牌标识采用用户于 2026-11-04 选定的[开口 P 精修稿](../../docs/design/reference-open-p-approved.png)：不对称圆腹、垂直竖笔、深浅蓝笔画及衔接处的小浅蓝折面；竖笔底端平收，不得向左撇。该确认稿替代旧的蓝底白色折带 P；门户其余灰蓝风格保持现有基准。

最新视觉依据为用户确认的 [FinanceFlow 导航参考图](../../docs/design/reference-neutral-blue-navigation.png)：白底、深灰文字、灰蓝线性图标、浅灰选中块、小面积蓝色品牌标识、细灰边框和低装饰。用户明确保留顶部导航，不采用参考图左侧栏。

参考图仅展示导航，首页按同一视觉语言延伸：白色应用卡、浅灰画布、深色标题、描边按钮，不复制 FinanceFlow 名称或金融业务菜单，不新增连接数据源等未实现功能。保持完整平台名“智选车计划部数据平台”与真实应用入口。

此前的[柔彩工作台参考](../../docs/design/reference-dashboard.png)仅作历史记录；新的中性灰蓝风格优先，不恢复紫色强调和大面积柔彩模块。ui-ux-pro-max 的简洁网格、清晰字级、焦点和对比度建议适用；其营销结构、推荐配色和外网字体不覆盖本参考。

紧凑布局补充依据：[用户标注图](../../docs/design/reference-compact-header.png)。标注要求将应用标签上移至品牌行，并压缩应用标题与空白。

## 布局与内容层级

1. 紧凑单行顶栏：蓝色开口 P、智选车/计划部数据平台、应用标签、现有身份信息同排。桌面高度约 64px，不再给标签单独分配一行。不要将默认工作空间当作已认证的域账号。
2. 顶部应用导航：工作台、SOP 计划看板、订单分析，以及配置启用的其他应用；选中项用浅灰背景、深色文字与蓝色图标，不加下划线或侧边色条。普通链接保留 `aria-current` 和 hash 深链接，不伪装成未实现键盘行为的 ARIA tabs。
3. 首页采用紧凑入口布局：工作台标题与真实注册数量、日期，一行“销售需求 → 销运平衡 → 入库计划”；不恢复大介绍区、英文眉题或独立三层流程卡。分组筛选和搜索在桌面同一工具带，窄屏按内容换行。可用应用桌面四列、平板两列、手机单列；每卡合并图标/名称/状态，保留用途、分组及一个打开操作，英文副标题不独占一行。待接入应用在下方以低强调横行展示。
4. 应用页：当前应用由顶部选中标签标识，不重复显示分组和应用名称；仅保留读屏可用的页面标题。正常应用页不显示额外状态/重新加载/返回工作台工具条；通过顶部标签切换。仅加载失败时在错误面板内显示重试按钮。此前 SOP 页脚及用户提示栏的调整作为已确认历史现状保留，不构成后续门户任务修改子应用的授权。以下规范仅约束门户外壳：正常访问时不显示“当前用户”或权限成功提示横栏，也不保留其空白；操作身份留在后台记录，服务异常时才显示必要提示。取消应用版本、数据更新时间和整个平台页脚，不保留其占位高度。上下间距约 8px，桌面工具按钮约 32px 高，手机保持 44px 点击高度；尽量把宽度和高度留给业务 iframe。门户主题不覆盖 iframe 内部业务样式。
5. 不新增无真实来源的 KPI、走势图、完成率、通知或头像。应用摘要只使用实际注册状态。

## 颜色令牌

以 `portal/css/portal.css` 的 `:root` 为运行时来源。颜色变化需同步本表。

| 令牌 | 值 | 用途 |
|---|---|---|
| `--bg` | `#F8FAFB` | 页面浅灰画布 |
| `--surface` | `#FFFFFF` | 顶栏、白色卡片 |
| `--surface-soft` | `#F0F5F6` | 导航选中、轻交互背景 |
| `--ink` | `#2C3436` | 标题和正文 |
| `--muted` | `#64717E` | 次要文字 |
| `--line` | `#E3E9EC` | 细边框和分隔 |
| `--accent` / `--ring` | `#1E6BC4` | 激活图标、链接与焦点 |
| `--accent-soft` | `#EDF5FF` | 应用图标浅底 |
| `--icon` | `#75818E` | 普通导航图标 |
| `--brand` | `#329AF0` | 小面积品牌强调，图标用色以导出器为准 |

蓝色用于小面积品牌、图标和交互强调，正文不使用低对比度的亮蓝色。业务卡片统一白底，不按应用分配紫/青大色块。状态通过文字配合颜色表达。

## 字体、尺寸、组件

- 使用本地字体栈 Segoe UI / Microsoft YaHei / PingFang SC / system-ui，保证内网无外部字体请求。
- 正文 14–16px；首页紧凑主标题 22–24px，应用名称 16px，用途 13px，分组和状态 12px。辅助标签可以更小，但参考图里的极小文字不可照搬；关键内容不小于 12px。
- 使用 4/8px 间距节奏，桌面内容最大 1320px，常用边距 32–48px，手机 16px。
- 主要卡片圆角 10px，按钮/输入框约 6–8px；边框 1px；静止状态不使用明显阴影，hover 可用 `0 2px 8px #26364106`，避免黑重影、厚框、发光和拟物效果。
- 可用应用卡片有清晰标题、用途、状态与一个操作，桌面高度约 145–170px，由内容自然撑开，不用固定高度截断名称或用途。四个入口不得再用两列大卡片占满多屏；1180px 及以下改为两列，640px 及以下单列。待接入卡片无伪操作；顶部状态页可解释尚未接入。
- 导航图标沿用现有一致的 SVG 线性图标，不用 emoji。品牌 P 以 2026-11-04 确认稿为准：白色圆角底、深蓝开口圆腹、亮蓝直竖和小浅蓝折面；圆腹可不对称，竖笔必须垂直向下且底端收齐，不得向左撇，不改成普通闭口字体 P。SVG/PNG/ICO 使用同一几何定义和配色，圆角外部透明；详细资产规则见下文“品牌资产维护”。
- Hover 约 180–200ms，只改颜色/边框/轻阴影，不移动版面；尊重 `prefers-reduced-motion`。

## 响应式与可访问性

- 1180px 及以下使用顶部展开导航；菜单展开推动页面内容，不变成侧边抽屉。选择后关闭，Escape 关闭并在需要时恢复按钮焦点。
- 640px 及以下主要入口单列，辅助应用纵向排列；搜索字号 16px，点击操作至少约 44px 高；不得产生整页横向溢出。
- 需检查 375、768、950、1024、1180/1181、1440px 附近。浏览器宽度或系统字号变化后不能挤掉平台名、数量、状态和按钮。
- 保留跳转主内容链接、可见键盘焦点、表单标签、`aria-current` 和错误状态说明。普通文字对比度至少 4.5:1；小字不可因追求淡色而不可读。

## 禁止的风格漂移

不恢复左侧栏或紫色/柔彩主题，不添加巨大深色首屏或营销大字，不把所有模块做成同等强调的大卡片，不用高饱和渐变/毛玻璃/3D/复杂背景。新增图表必须有真实业务数据及合适的空态，不能用假数字来“丰富”首页。

## 品牌资产维护

确认稿只作参考，运行资产以 `portal/assets/planning-icon.svg` 为主；门户图标用于顶部、浏览器标签与移动收藏，不修改子应用图标或系统快捷方式。生产图形由矢量路径重建，去掉预览外围留白；保持开口圆腹、直竖和浅蓝折面。

SVG、PNG、ICO 共用 `scripts/export-planning-icon.py` 的几何和配色；白色圆角底的角外透明，不依赖系统字体或外网资源。更新生产资产时修改导出器并执行 `python scripts/export-planning-icon.py`，生成 SVG、512/180/32px PNG 与含16/32/48/64px的ICO。Pillow仅用于开发导出，不是运行依赖。同步更新 `portal/index.html` 图标资源版本参数，核对16/32px轮廓、留白和竖笔，以及深色浏览器标签栏中的可见性。

顶栏沿用36×36显示尺寸；旁边已有平台文字，HTML保留空alt与aria-hidden避免读屏重复。详细确认过程和验收结果归档于[实施与验证档案](../../docs/history.md)。
