# 智选车计划部工作台 UI 规范

修改首页、侧栏或应用加载状态时，以本文为准。门户样式复用同一套 CSS 变量和组件。调整已确认的尺寸、颜色或交互时，在同一次修改中更新规范和验收结果。[门户样式](../../portal/css/portal.css)

## 品牌与文字

- 首页主标题使用完整产品名 **智选车计划部工作台**。侧栏收起时显示 36px 标志，展开时首行并排放置 24px 标志和“智选车”，第二行显示“计划部工作台”，字级 19px、字重 600。
- 沿用已确认的 Shopeers 风格，使用白色侧栏和卡片、浅灰画布、细描边与钴蓝强调。标志保留透明底、深蓝开口圆腹、亮蓝直竖和浅蓝折面。侧栏和浏览器图标使用同一图形，由同一脚本生成 SVG、PNG 和 ICO。[外观参考](https://dribbble.com/shots/26628350-Shopeers-AI-Powered-B2B-eCommerce-Analytics-Dashboard) · [品牌确认图](../../docs/design/reference-open-p-approved.png) · [侧栏标志](../../portal/assets/planning-icon.svg) · [图标导出脚本](../../scripts/export-planning-icon.py)
- 每段可见文字都应帮助同事判断去哪里、执行什么操作或了解当前状态。清单用“核对共享数据原表”这样的动作名称。应用目录使用注册表中的一句介绍。省去演示指标、宣传语、功能教程和重复提示。

## 颜色与字级

| 用途 | 取值 | 使用位置 |
| --- | --- | --- |
| 画布、表面、分隔 | `--bg` #F4F6F9、`--surface` #FFFFFF、`--line` #E5E7ED | 首页底色、侧栏和卡片、1px 描边 |
| 正文、辅助文字 | `--ink` #0B0D17、`--muted` #606775 | 标题与正文、次要日期和来源 |
| 强调、深蓝、浅蓝 | `--accent` #2859F5、`--accent-hover` #2049D4、`--accent-soft` #EDF2FF | 主操作和焦点、选中文字、选中底色 |
| 状态 | 正向 #14764A、提醒 #8B601F、负向 #B72D59 | 状态同时用文字说明，图表用标签区分序列 |

| 层级 | 尺寸和字重 |
| --- | --- |
| 首页主标题 | 19px / 700，行高 1.45 |
| 面板标题、应用名称 | 16px / 650–700 |
| 正文、常规控件 | 14px。展开侧栏的导航文字为 16px / 400 |
| 表格数据、辅助信息 | 数据 13px，说明、来源和日历周次 12px。日期与指标使用等宽数字 |

字体从本机加载。标题优先使用 Noto Sans SC，正文和侧栏优先使用 Segoe UI，中文回退至微软雅黑或苹方。字号优先复用 `--type-title`、`--type-section`、`--type-body`、`--type-note`。

## 布局与导航

下表宽度指浏览器视口，尺寸单位为 CSS 像素。首页在侧栏右侧居中，内容最大宽度 1440px。

| 视口宽度 | 侧栏收起 / 展开 | 首页左右留白 | 阶段卡 | 清单与日历 | 应用目录 |
| --- | --- | --- | --- | --- | --- |
| ≥1040px | 56 / 145 | 24 | 4 列 | 左右两栏 | 3 列 |
| 821–1039px | 56 / 145 | 20 | 4 列 | 左右两栏 | 2 列 |
| 641–820px | 56 / 145 | 20 | 2 列 | 上下排列 | 2 列 |
| ≤640px | 48 / 145 | 10 | 2 列 | 上下排列 | 1 列 |

首页的阶段卡与面板使用 1px 描边、轻阴影、20px 圆角，网格间距 16px。在 640px 及以下，圆角缩至 16px，间距缩至 10px，长名称允许换行。

侧栏贴左，内容区从顶边开始。品牌行高 64px，工作台入口行高 56px，第二行底边距顶部 120px。应用入口之间留 16px。每个入口至少 44px 高，圆角 10px，线性图标 22px，展开时图文间隔 6px。底部按钮展开或收起侧栏，浏览器记住选择，刷新或切换页面后沿用。

## 首页如何引导办事

| 区域 | 设计约定 |
| --- | --- |
| 阶段卡 | 依次为 01 数据准备、02 需求预测、03 入库计划、04 协同复核。选中阶段只切换下方清单，编号表示顺序。 |
| 办事清单、计划记录 | 清单项展示动作和目标应用，整行进入对应网页。门户不记录完成进度。“计划记录”进入 SOP管理，编制周期和已保存的记录以该应用为准。 |
| 订单日历 | 按北京时间定位本月，从周一排到周日，左列显示 ISO 周次。订单批注按事件日期展示，同日同文的跨主体阶段事件合并。今天用钴蓝实底标出。有标注的日期可展开全文。日历容器宽度 ≤420px 时仅显示条数，保留详情入口。 |
| 全部应用 | 与侧栏共用注册表，只列出已启用应用。可用应用显示名称、简介和入口。待接入、维护中的项目在首页显示状态文字，侧栏可打开对应状态页。 |

窄屏按办事清单、计划记录、订单日历、全部应用的顺序阅读。日历分别提示加载中、本月暂无标注和来源读取失败。某一来源失败时保留已读到的标注，并提供重试。[阶段与办事清单](../../portal/js/workflow.js) · [应用注册表](../../portal/config/apps.json)

## 内嵌业务页

| 位置 | 约定 | 维护方 |
| --- | --- | --- |
| 侧栏右侧的页面容器 | 同源 iframe 填满可用宽高，从顶边开始，容器内边距和边框均为 0，使用直角。 | 门户 |
| 业务标题和顶部导航 | 桌面工具行 64px，导航行 56px（含底部分隔线），导航底边与侧栏 120px 分隔线对齐。内嵌标题 19px / 700，行高 1.15。从工作台打开时隐藏标题左侧产品图标，同时收起占位；独立打开时保留原图标。 | 子应用 |
| 导航与首块看板 | 从导航底边量到首块可见看板的顶边，桌面为 16px，640px 及以下为 12px。桌面长导航保持单行，可横向滚动。窄屏可使用模块下拉框或将操作换行，宽表格在表格区内滚动。 | 子应用 |

子应用在自己的仓库实现嵌入样式。门户通过公开入口展示页面，禁止向子页注入 CSS、脚本或改写页面响应。接入方式及嵌入标记见[应用接入手册](../../docs/child-app-developer-guide.md#页面必须满足的约定)。

## 交互、状态与键盘操作

- 进入应用使用链接，切换阶段、翻月和重试使用按钮。次要操作用白底细边框。清单行以细线分隔，表头用浅灰底，悬停时保留文字对齐。手机上的主要操作预留至少 44px 点击高度。
- 导航选中使用浅蓝底、深蓝文字，当前入口标记 `aria-current="page"`。阶段按钮用细蓝边和 `aria-pressed` 表示选择。悬停约 160ms 变色，保持尺寸与位置稳定。
- 纯图标控件要有可读名称。键盘可从“跳转到工作区”直接进入正文。默认焦点环为 3px 钴蓝，侧栏导航链接为 2px 内轮廓。展开按钮用 `aria-expanded` 同步状态。尊重系统的减少动态效果设置。
- 打开应用时显示加载状态，超时或失败时给出原因和“重新加载”操作。成功打开的 iframe 在切换应用时保留，只有当前页面可见并参与键盘导航。业务数据刷新由子应用负责。

## 界面改动如何验收

1. 从门户根目录运行 `npm run check` 和 `npm test`。启动开发版后从首页进入真实应用，具体命令见[开发联调](../../README.md#开发联调)。
2. 在 **1440px 和 390px** 各检查一次侧栏展开、收起和刷新。桌面核对 120px 分隔线是否对齐，手机操作一次折叠或换行后的导航。两种宽度均核对导航到看板的间距，以及整页有无横向溢出。改动断点时也检查断点两侧。
3. 用鼠标和键盘切换阶段，打开清单项和计划记录，翻月并展开一条订单标注。从目录进入应用后切回，检查焦点、加载和重试，再用测试配置核对待接入与维护状态。涉及标题图标时，对照同一应用的内嵌与独立页面。
4. 留存本次改动的桌面和手机截图。侧栏回归使用[固定样例截图](../../tests/visual-baselines)。经确认需要更新侧栏基线后，在 Windows Edge、Playwright、Pillow 环境中设置 `PLANHUB_UPDATE_VISUAL_BASELINES=1`，运行 `..\.venv\Scripts\python.exe -B -m unittest discover -s tests -p test_app_navigation.py`，清除该变量后复测。
