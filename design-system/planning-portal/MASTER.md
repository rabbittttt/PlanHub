# 计划部数据平台 · 界面设计基准

确认日期：2026-11-03。适用范围：统一门户外壳及其后续新增页面、组件；不适用于 iframe 内的子应用。门户任务不得修改子应用 UI、源码或行为，也不得通过注入、裁剪或响应改写间接修改。入口指引见根目录 `AGENTS.md`。

## 视觉依据与取舍

用户确认的[参考图](../../docs/design/reference-dashboard.png)是视觉基准：白色工作区、极浅冷色背景、淡青/淡紫/淡粉/淡桃模块、柔和阴影、细描边、简洁无衬线字和宽松间距。重点是轻盈、清晰、精致的分析工作台。

参考图只提供视觉语言。用户明确要求应用标签置于顶部，因此不复制图中的侧边栏。也不复制图中的英文业务、数字、头像、装饰图表或过小字体。门户内容围绕销售与运作计划：销售需求、未来各期入库量、订单分析。

ui-ux-pro-max 的企业仪表盘检索支持简洁网格、明确层级、可见焦点与轻交互；配色和圆角以本参考稿和实际令牌为准，不照搬技能返回的其他行业主题。

紧凑布局补充依据：[用户标注图](../../docs/design/reference-compact-header.png)。标注要求将应用标签上移至品牌行，并压缩应用标题与空白。

## 布局与内容层级

1. 紧凑单行顶栏：双色折带 P、智选车/计划部数据平台、应用标签、现有身份信息同排。桌面高度约 64px，不再给标签单独分配一行。不要将默认工作空间当作已认证的域账号。
2. 顶部应用导航：工作台、SOP 计划看板、订单分析，以及配置启用的其他应用；选中项用淡紫底和紫色下划线。普通链接保留 `aria-current` 和 hash 深链接，不伪装成未实现键盘行为的 ARIA tabs。
3. 首页：简洁业务标题与日期；以文字说明销售需求→销运平衡→入库计划；SOP 与订单作为主要入口，待接入应用在下方低强调呈现。
4. 应用页：当前应用由顶部选中标签标识，不重复显示分组和应用名称；仅保留读屏可用的页面标题。正常应用页不显示额外状态/重新加载/返回工作台工具条；通过顶部标签切换。仅加载失败时在错误面板内显示重试按钮。此前 SOP 页脚及用户提示栏的调整作为已确认历史现状保留，不构成后续门户任务修改子应用的授权。以下规范仅约束门户外壳：正常访问时不显示“当前用户”或权限成功提示横栏，也不保留其空白；操作身份留在后台记录，服务异常时才显示必要提示。取消应用版本、数据更新时间和整个平台页脚，不保留其占位高度。上下间距约 8px，桌面工具按钮约 32px 高，手机保持 44px 点击高度；尽量把宽度和高度留给业务 iframe。门户主题不覆盖 iframe 内部业务样式。
5. 不新增无真实来源的 KPI、走势图、完成率、通知或头像。应用摘要只使用实际注册状态。

## 颜色令牌

以 `portal/css/portal.css` 的 `:root` 为运行时来源。颜色变化需同步本表。

| 令牌 | 值 | 用途 |
|---|---|---|
| `--bg` | `#FBFBFE` | 页面背景 |
| `--surface` | `#FFFFFF` | 顶栏、白色模块 |
| `--surface-soft` | `#F6F5FB` | 输入框与辅助背景 |
| `--ink` | `#272438` | 主文字 |
| `--muted` | `#69667E` | 次要文字 |
| `--line` | `#ECEBF4` | 细边框与分隔 |
| `--accent` / `--ring` | `#6550B9` | 主按钮、当前项、焦点 |
| `--pastel-lilac` | `#F3EDFF` | SOP 模块 |
| `--pastel-cyan` | `#EDFBFC` | 订单分析模块 |
| `--pastel-peach` | `#FFF3EC` | 后续辅助模块备选 |
| `--pastel-rose` | `#FFF0F2` | 后续辅助模块备选 |
| `--brand` | `#6550B9` | 品牌紫色 |

淡色用于大面积背景，深色用于文字和主操作。每个模块最多一组强调色，避免彩虹式按钮。成功、维护、待接入状态应同时带文字，不只靠颜色。

## 字体、尺寸、组件

- 使用本地字体栈 Segoe UI / Microsoft YaHei / PingFang SC / system-ui，保证内网无外部字体请求。
- 正文 14–16px，主标题约 28–33px，模块标题 20–23px。辅助标签可以更小，但参考图里的极小文字不可照搬；关键内容不小于 12px。
- 使用 4/8px 间距节奏，桌面内容最大 1320px，常用边距 32–48px，手机 20px。
- 主要卡片圆角 16px，次级卡片 10px，按钮/输入框 7–8px；边框 1px；轻阴影 `0 12px 36px #423B7810`，避免黑重影、厚框、发光和拟物效果。
- 可用应用卡片有清晰标题、用途、状态与一个操作。待接入卡片无伪操作；顶部状态页可解释尚未接入。
- 图标沿用现有一致的 SVG 线性图标，不用 emoji，不随意改 P 形状和比例。P 标识使用浅紫底 #F3EDFF、深紫上部 #6550B9、柔紫竖笔 #8B75C9，SVG/PNG/ICO 保持一致。
- Hover 约 180–200ms，只改颜色/边框/轻阴影，不移动版面；尊重 `prefers-reduced-motion`。

## 响应式与可访问性

- 1100px 及以下使用顶部展开导航；菜单展开推动页面内容，不变成侧边抽屉。选择后关闭，Escape 关闭并在需要时恢复按钮焦点。
- 640px 及以下主要入口单列，辅助应用纵向排列；搜索字号 16px，点击操作至少约 44px 高；不得产生整页横向溢出。
- 需检查 375、768、950、1024、1440px 附近。浏览器宽度或系统字号变化后不能挤掉平台名、数量、状态和按钮。
- 保留跳转主内容链接、可见键盘焦点、表单标签、`aria-current` 和错误状态说明。普通文字对比度至少 4.5:1；小字不可因追求淡色而不可读。

## 禁止的风格漂移

不恢复深色左侧栏，不添加巨大深色首屏或营销大字，不把所有模块做成同等强调的大卡片，不用高饱和渐变/毛玻璃/3D/复杂背景。新增图表必须有真实业务数据及合适的空态，不能用假数字来“丰富”首页。

## 交付检查

运行 `npm run check`；检查实际桌面和手机截图、无横向溢出、当前应用状态、搜索和分组、无结果状态、待接入状态、可用应用 iframe 载入及返回。涉及主题变化时同步更新本文、CSS 令牌和 `docs/branding.md`。保留参考图；无需每次生成新设计系统。
