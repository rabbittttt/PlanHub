用户于 2026-11-03 确认：**门户只做集成，不修改各子网页的逻辑、UI 等任何内容；此前已完成的改动保留，今后严格分开。** 本约定优先于历史文档中的“适配原项目”表述。

## 门户任务可以做什么

- 修改门户自己的首页、顶栏导航、入口注册、加载与错误状态。
- 维护门户侧静态挂载、受控代理、预览、构建产物校验与打包逻辑。
- 只读核对子应用的版本、路径、现有接口和构建说明；按其已有公开参数启动服务或使用负责人提供的原样发布物。
- 使用隔离数据验收接入效果，记录实际问题。路径沿用门户根目录相对路径约定。

## 门户任务不能做什么

- 不修改子应用的源码、UI、文案、图标、业务计算、操作流程、权限实现、数据规则、数据库、测试或协作规范。
- 不因主题统一、紧凑布局、部门权限一致或方便嵌入，就调整子应用页面、页脚、提示栏或按钮。
- 不改写子应用发布物，不操作 iframe 内的 DOM，不注入 CSS/JavaScript，不裁剪内容，不替换代理响应正文，不剥除子应用的安全响应头。
- 不自动修复子应用的问题，也不把复制出的修改版作为另一套业务源码。
- 不把默认 Git 提交/推送约定理解为可写入、提交或推送子应用仓库的授权。

## 遇到接入冲突怎么办

先尝试子应用已有的配置参数和门户侧标准映射。若仍缺少子路径、内嵌或身份能力，记录具体表现、原项目文件/接口、必要改动及影响，保留未接入状态或明确受限范围。用户另行明确授权子应用任务后，才在该任务内处理；不能以“接入必须”为由直接改动。

门户的部门统一权限约定只约束门户入口，不授予门户任务修改子应用权限实现的权限。子应用已有规则与接入需求冲突时，同样按上述流程处理。
