## 启动、停止和重启

首次使用需安装 Node.js 20+，并准备原业务项目及其依赖。工作区共享 Python 环境使用 3.11+；默认从门户位置向上寻找名为 `Project` 的目录，使用其中的 `.venv`。换电脑后重新创建环境，不复制旧 `.venv`；门户不会自动安装各项目依赖。

| 操作 | 双击文件 | 命令行 |
|---|---|---|
| 启动 | `启动本地门户.cmd` | `npm start` 或 `npm run dev` |
| 停止 | `停止本地门户.cmd` | `npm stop` |
| 完整重启 | 先停止，再启动 | 先 `npm stop`，再 `npm start` |

默认浏览器地址为 `http://127.0.0.1:4173/`，以启动窗口实际打印的地址为准。保持第一次负责运行服务的窗口打开；仅关闭浏览器页面不会停止服务。后台实例即使没有可见窗口，也可通过停止入口结束。

重复启动会核对实例、工作区、代码版本、有效配置及后端健康状态；同一套健康门户直接复用，不启动第二份 SOP 或数据速查。正常复用后的临时启动窗口可以关闭。若代码、数据目录、运行模式或后端端口不同，先停止旧实例再启动。

停止命令只停止匹配门户及其创建的后端进程树，已独立启动并被门户复用的服务继续由原项目管理。不要另开 SOP 独立启动器，让两个服务同时写同一数据库或维护表。

自定义端口示例：

```sh
npm start -- --port 4176 --backend-port 8879
```

对应停止命令为 `npm stop -- --port 4176`。更改端口前核对占用情况；不会自动结束其他程序。

`npm run dev:static` 只提供静态门户和已配置的代理，不启动 SOP 或其他后端。正常日常操作使用 `npm start`；当前仍是本机入口，部门内网部署另见[部署指南](deployment.md)。

## 应用和数据放在哪里

门户只负责外壳、导航和接入，各网页源码及业务数据仍由原项目维护。默认布局如下；父目录盘符和门户文件夹名可以改变，但需保留相对位置，或在本机配置中覆盖。

| 应用/内容 | 默认相对路径或公共地址 | 保存与更新方式 |
|---|---|---|
| SOP 唯一源码 | `../SOP维护`；页面 `/sop/` | 门户直接启动原项目服务 |
| SOP 数据库 | `../SOP维护/data/sop.sqlite3` | 网页维护直接持久保存 |
| SOP 销售数据与来源设置 | `../SOP维护/data/sales.json`、`source_settings.json` | 由原项目刷新和维护 |
| 销售输入 | `../共享数据/订单汇总` | 各项目按已有规则读取 |
| SOP 计划维护表 | `../共享数据/SOP计划/SOP计划维护.xlsx` | 原应用负责网页与 Excel 同步 |
| 共享业务规则 | `../订单分析/scripts/config/shared_config.py` | 由原规则项目维护，门户只引用 |
| 订单分析报表 | `apps/orderiq/index.html`；页面 `/orderiq/` | 从原项目生成的业务发布物导入 |
| 销量预测发布物 | `../销量预测/output_file/鸿蒙智行销量预测.html` 和 `forecast_assets/`；页面 `/forecast/` | 本地直接挂载原项目完整发布物 |
| 数据速查服务 | `../数据速查/server.py`；页面 `/quicklook/` | 独立服务，默认回环端口 8765 |
| 数据速查私有数据 | `../数据速查/output_file/` | 数据库、配置和缓存由原项目持久维护 |

**SOP 日常操作使用原项目持久数据，重启不会换成新快照。** 已有 Excel 维护表按原应用规则同步；未创建维护表时，数据库仍能保存，是否创建由原应用的“创建Excel（可选）”操作决定。Excel 占用、版本冲突或同步失败按原应用提示处理，门户不强制覆盖。

无共享根目录时，SOP 沿用原项目的 `input_file/`。共享根存在但缺少销售来源目录时会明确报错，不自动读取旧副本。

门户在 `artifacts/sop-runtime-*/` 中保存接入配置和运行日志，不存放日常操作用的另一套业务数据库。SOP 自带备份在原数据目录的 `backups/` 下。历史 `artifacts/sop-preview-*`、发布备份及恢复资料保留；历史验证结果见[历史记录](history.md)。

只有测试人员显式选择 `--snapshot` 才使用隔离副本；历史 `--seed-from` 必须与它配合。演示命令为 `npm run dev:sop -- --snapshot --demo`。日常启动不添加这些参数。

## 调整本机配置

本机配置位于被 Git 忽略的 `config.local/`，配置中的相对路径仍按**门户根目录**解析，与当前终端目录及配置文件所在目录无关。浏览器业务地址使用 `/sop/` 这类同源 URL，不要与磁盘路径混淆。

### SOP 的源码、数据与规则

`config.local/sop.json` 的示例：

```json
{
  "sourceRoot": "../SOP维护",
  "sharedConfig": "../订单分析/scripts/config/shared_config.py"
}
```

- `sourceRoot` / `--sop-source` 选择唯一业务源码，目录应包含 `server.py`、`sop/gateway.py` 和 `web/`。
- `dataRoot` / `--data-root` 可指定另一个包含 `data/`、`input_file/` 的持久数据项目；默认无需填写，使用原 SOP 数据与共享输入。
- `sharedConfig` / `--shared-config` 选择共享规则文件。
- 源码选择优先级为 CLI、`SOP_SOURCE_ROOT`、本机配置、默认兄弟项目。源码和数据选择相互独立，不回退到门户 `services/sop` 的旧业务副本。

还可使用 `SOP_DATA_DIR` 直接选择数据库目录，`SOP_SOURCE_DIR`、`SOP_PLAN_DIR` 分别选择销售及计划目录，`SHARED_DATA_ROOT` 选择共享根目录。门户运行时这些变量的相对路径也按门户根目录解析。显式 `dataRoot` 默认使用其中的 `data/` 和 `input_file/`；若要改用其他共享输入，明确配置对应路径。

显式解释器配置为 `SOP_PYTHON_PATH`（兼容旧 `SOP_PYTHON`），例如 `../.venv/Scripts/python.exe`。门户会验证 Python 和原 SOP 依赖，环境缺失或损坏时明确报错，不自动切换其他环境。

### 销量预测、数据速查及其他接入

默认接入清单为 `integration/apps.json`，可用 `config.local/apps.json` 覆盖应用字段。例如项目文件夹更名后：

```json
{
  "applications": {
    "forecast": { "root": "../预测项目/output_file" },
    "quicklook": {
      "start": {
        "cwd": "../查询项目",
        "command": "../.venv/Scripts/python.exe",
        "args": ["-B", "server.py"]
      }
    }
  }
}
```

每个应用的字段合并覆盖；`start` 为完整对象，设为 `null` 时只连接手动管理的服务。`root`、`cwd`、`command` 相对门户根目录解析。数据速查当前原项目固定监听 8765，单改门户 `target` 不会改变它的监听端口；监听参数需求应在原项目单独处理。

新增网页、资源白名单、代理规则和交付要求见[应用接入规范](child-app-developer-guide.md)。

## 更新页面与业务数据

- **订单分析**：在原项目按其规则生成新报表，再通过 `scripts/Import-OrderIQ.ps1` 导入实际发布 HTML。报表已包含的业务数据会随页面提供给访问者，不提交公开 Git。
- **销量预测**：在原项目生成新 HTML，保留同目录 `forecast_assets/`。门户本地直接读取这些发布文件，刷新页面即可加载当前版本；门户不会自动重算预测。
- **SOP**：网页保存直接写原数据库；销售数据刷新、Excel 同步和冲突处理继续由 SOP 原实现负责，不需要重启门户复制数据。
- **数据速查**：原项目负责数据源设置、数据库和自动同步。页面上的导入、设置修改按原规则持久保存，门户不改成临时数据库，也不合并各项目数据库。更新后端程序后需重启服务。

切换到门户地址后，旧独立地址中的浏览器收藏/草稿不会自动迁移；换浏览器、清理站点存储或换电脑同样需要自行迁移。应由部门共同保存的数据需使用业务服务端已有的持久保存能力。

## 迁移到另一台电脑

1. 确认下载的是门户仓库 `https://github.com/rabbittttt/PlanHub.git`；各业务项目使用各自的仓库。
2. 迁移项目及共享数据，保留相对布局；公开 Git 不包含真实 Excel、数据库、生成的业务报表、本机配置或恢复备份，需另行安全迁移。
3. 安装 Node.js 20+、工作区要求的 Python 3.11+，重新创建 `Project/.venv` 并安装原项目依赖。可运行工作区已有的 `初始化共享环境.cmd`；不要直接复制旧虚拟环境。
4. 核对 `config.local/sop.json`、`config.local/apps.json` 及路径环境变量，再从门户根目录启动。
5. 验证各页面及必要的查询、保存、导入导出，并确认停止重启后仍读回已保存数据。

### 已 git pull，却缺少门户 CMD

**文件夹名不代表仓库身份。** 曾出现名为“计划工作台”的目录实际连接 SOP 仓库，因此拉取后只有 SOP 的启动脚本。先在执行 pull 的目录运行以下只读命令；它们可直接用于 Git Bash：

```sh
git rev-parse --show-toplevel
git remote -v
git branch --show-current
git log -1 --oneline
git -c core.quotepath=false ls-files -- '*.cmd' '*.bat'
git status --short --untracked-files=all -- '*.cmd' '*.bat'
ls -1 *.cmd *.bat 2>/dev/null
```

正确门户仓库包含 `启动本地门户.cmd` 和 `停止本地门户.cmd`。若远程和提交属于 SOP，保留该目录和业务数据，另外克隆正确门户，再配置原 SOP 的相对位置；不要直接把不同项目的远程地址换成同一个来混合历史。多余脚本若是本机未跟踪或忽略文件，`git pull` 不会自动删除，先核对归属再处理。

PowerShell 可使用 `Get-ChildItem`；Git Bash 使用 `ls`，两种终端的文件命令不能直接混用。

## 常见故障

| 表现 | 先检查什么 |
|---|---|
| SOP 页面 404 | 是否误用 `dev:static`、Live Server 或没有代理规则的 IIS；源码和 gateway 是否存在 |
| 订单分析 404 | `apps/orderiq/index.html` 是否已导入；Git 不包含业务 HTML |
| 销量预测 404/资源缺失 | 原项目 HTML 是否已生成，`forecast_assets/` 是否完整；接入路径是否正确 |
| 数据速查不可用 | 独立服务是否健康、8765 是否被其他程序占用、本机接入配置是否指向实际项目 |
| 提示端口已占用 | 先用停止入口结束匹配门户再启动；其他工作区或未知程序不会被自动停止 |
| 提示源码、规则或数据不存在 | 按实际目录核对本机配置和环境变量，不用空文件或演示数据代替业务数据 |
| 缺少 Python/模块 | 重建共享环境并按原项目 requirements 安装，确认实际解释器路径 |
| 直达业务地址正常，iframe 失败 | 检查同源地址、嵌入响应头、跳转前缀；刷新缓存；必要时由原应用负责人处理 |
| 页面仍是旧版本 | 核对正在运行的实例/代码版本及实际发布物；代码更新后完整停止并启动，页面可 Ctrl+F5 |

### 两个后端有端口，却一直超时

曾定位到 Windows 控制台文本选择暂停日志写入，导致 Python 请求处理阻塞。当前后端 stdout/stderr 直接写独立文件，不继承控制台；旧进程需重启才能获得修复。端口存在本身不代表服务健康。

日志位置在启动时打印：SOP 为 `artifacts/sop-runtime-*/logs/`，其他服务为 `artifacts/service-<id>-*/`；SOP 自身日志还可能在原数据目录。根据具体日志检查原项目异常，不修改子页面来掩盖服务故障。

### 关闭旧窗口后仍提示 4173 占用

后台恢复启动的实例可能没有可见窗口，关闭另一个旧窗口不会结束它。使用 `停止本地门户.cmd` / `npm stop` 后再启动。实例记录保存在忽略的 `artifacts/portal-instances/<port>-<instanceId>.json`；管理地址 `/api/portal/health`、`/api/portal/stop` 由启动器保留。不要按端口强杀未知进程或手工删除记录来当作停止服务。

内网 IIS 的域名、身份与部门访问边界问题需在目标服务器验收，详见[部署指南](deployment.md)。
